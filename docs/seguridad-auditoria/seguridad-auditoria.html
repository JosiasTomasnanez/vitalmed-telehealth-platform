🛡️ Flujo de Seguridad y Auditoría de la Plataforma

La seguridad se aplica antes, durante y después de una petición. El objetivo es que los controles preventivos, la detección de amenazas y la evidencia de auditoría funcionen automáticamente en las cuatro cuentas de país.

🚧 01. PREVENIR ANTES
Amazon CloudFront

Punto de entrada público de la aplicación.

↓
AWS WAF

Filtra solicitudes HTTP/HTTPS mediante Web ACL, reglas administradas y límites de tasa.

↓
ALB → Microservicios

Solo las peticiones que superan el control perimetral continúan hacia la aplicación.

🔎 02. DETECTAR DURANTE
AWS CloudTrail

Registra actividad de la cuenta y llamadas API, dejando evidencia de identidad, acción, recurso y momento.

Amazon GuardDuty

Detecta comportamientos y amenazas sospechosas en las cuentas de AWS.

AWS Config

Evalúa continuamente la configuración de los recursos contra reglas y Conformance Packs.

🚨 03. CENTRALIZAR DESPUÉS
AWS Security Hub

Consolida hallazgos y postura de seguridad para evitar revisar cuatro cuentas por separado.

↓
Equipo de 12 personas

Recibe únicamente los eventos que requieren análisis o intervención, en lugar de revisar manualmente cada cuenta.

Resultado operativo

Menos tareas manuales, evidencia trazable y una postura de seguridad homogénea.

Separación por país

Argentina, Chile, Colombia y México mantienen sus recursos y datos en cuentas AWS independientes. Los controles de seguridad y compliance se gobiernan desde AWS Organizations, mientras que los hallazgos pueden centralizarse operativamente sin mezclar las HCE entre países.

🔐 Servicios de Seguridad, Auditoría y Cumplimiento

Cada servicio tiene una responsabilidad concreta. No se busca sumar herramientas, sino eliminar controles manuales y generar evidencia verificable para una plataforma que maneja datos de salud.

AWS WAF PREVENCIÓN

Protección de las aplicaciones web antes de llegar al ALB. Permite aplicar reglas administradas, filtros sobre las solicitudes y rate limiting.

  • Bloqueo de patrones de tráfico malicioso.
  • Reglas específicas para endpoints sensibles.
  • Rate-based rules para abuso o picos anómalos.
  • Configuración reproducible mediante Terraform.
AWS CloudTrail AUDITORÍA

Fuente de evidencia de actividad de las cuentas AWS. Permite investigar quién ejecutó una acción, qué servicio utilizó y cuándo ocurrió.

  • Historial de actividad de las cuentas.
  • Management events para operaciones de administración.
  • Data events cuando se necesita mayor detalle sobre recursos compatibles.
  • La auditoría de acceso funcional a una HCE debe complementarse con eventos de aplicación cuando corresponda.
AWS Config + Conformance Packs COMPLIANCE

Convierte requisitos de seguridad en reglas comprobables. Un Conformance Pack agrupa controles y puede desplegarse de forma organizacional.

  • Reglas versionadas como YAML.
  • Aplicación homogénea a las cuentas de Argentina, Chile, Colombia y México.
  • Historial de compliance y detección de drift.
  • Posibilidad de incorporar remediation actions donde tenga sentido.
Amazon GuardDuty DETECCIÓN

Detección administrada de actividad potencialmente maliciosa o anómala. Se integra con AWS Organizations para administrar las cuentas miembro desde un administrador delegado.

  • Un punto operativo para revisar findings de las cuentas.
  • Auto-enable para nuevas cuentas de la organización.
  • Reduce la necesidad de revisar manualmente cada cuenta.
AWS Security Hub POSTURA CENTRAL

Punto de consolidación de findings y controles de seguridad. Con configuración centralizada, un administrador delegado puede aplicar políticas coherentes a cuentas y OUs.

Un solo tablero

Evita saltar entre cuatro cuentas para conocer la postura general.

Políticas centrales

Estándares y controles definidos desde la cuenta administradora.

Menos drift

Reduce configuraciones diferentes entre cuentas.

⚙️ Gobernanza Automatizada con Terraform

Para un equipo de aproximadamente 12 personas, el valor principal no es tener más controles sino conseguir que los controles sean repetibles, versionados y verificables.

📦

Código como fuente de verdad

WAF, CloudTrail, Config, GuardDuty y Security Hub se modelan en Terraform cuando el recurso/configuración es administrable como IaC. Los cambios pasan por Git, revisión y pipeline.

🔁

Mismo control en 4 cuentas

Los módulos de Terraform evitan copiar configuraciones a mano. Se parametriza la cuenta/país y se reutiliza la misma política de seguridad.

🧾

Evidencia auditable

Git conserva quién cambió la configuración de infraestructura; AWS conserva la evidencia de actividad y compliance. Se separan claramente ambas fuentes.

Principio operativo

"El equipo no debería descubrir manualmente que una cuenta quedó insegura."

La infraestructura se declara en código, las configuraciones se evalúan automáticamente y los findings se centralizan. La intervención humana queda reservada para excepciones, análisis y decisiones.

📘 Decisiones de Arquitectura Asociadas (ADRs)

Decisiones orientadas a seguridad, trazabilidad y reducción de carga operativa para un equipo reducido que opera una plataforma sanitaria en cuatro países.

ADR-SEC-001 Aprobado

WAF en el borde con CloudFront

Decisión: Proteger el punto de entrada web mediante AWS WAF asociado al flujo de CloudFront.

✓ Beneficio: el tráfico no deseado se filtra antes de alcanzar el ALB y los microservicios, reduciendo exposición y trabajo operativo.

ADR-AUD-001 Aprobado

CloudTrail como evidencia central de actividad AWS

Decisión: Mantener CloudTrail como fuente de auditoría de las operaciones de AWS y habilitar el nivel de eventos necesario para los recursos que requieran mayor trazabilidad.

✓ Beneficio: ante una investigación, el equipo puede reconstruir actividad sin depender de memoria humana o registros manuales.

ADR-CMP-001 Aprobado

Compliance como código con AWS Config

Decisión: Definir las reglas de compliance mediante AWS Config y Conformance Packs, gestionando su configuración de forma reproducible.

✓ Beneficio: las cuatro cuentas se evalúan con una política común y los cambios pueden revisarse/versionarse como infraestructura.

ADR-SEC-002 Aprobado

GuardDuty administrado desde una cuenta delegada

Decisión: Utilizar AWS Organizations para administrar GuardDuty en las cuentas miembro desde un administrador delegado.

✓ Beneficio: se evita operar cuatro configuraciones independientes y se facilita incorporar nuevas cuentas de forma automática.

ADR-SEC-003 Aprobado

Security Hub como punto central de postura de seguridad

Decisión: Centralizar la gestión de la postura y los findings de seguridad mediante Security Hub y una cuenta administradora delegada, manteniendo separadas las cuentas de país.

✓ Beneficio: el equipo de 12 personas obtiene una visión operativa única sin eliminar el aislamiento de las cuentas ni de los datos de cada país.

ADR-IAC-001 Aprobado

Seguridad reproducible mediante Terraform

Decisión: Tratar la configuración de seguridad administrable como IaC, con módulos reutilizables por país y cambios sujetos a Git/peer review.

✓ Beneficio: evita configuraciones manuales divergentes y permite validar los cambios antes de aplicarlos. Esto es especialmente relevante para un equipo de 12 personas.

ADR-AUD-002 Supuesto / Validar

Auditoría de acceso a la HCE a nivel de aplicación

Decisión: No considerar que CloudTrail por sí solo resuelve la trazabilidad funcional de "qué profesional vio qué HCE". La aplicación debe generar eventos de auditoría cuando se requiera ese nivel de detalle.

✓ Beneficio: evita una falsa sensación de cumplimiento y separa correctamente la auditoría de AWS de la auditoría funcional del negocio sanitario.
