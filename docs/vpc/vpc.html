Estrategia de 3 capas lógicas distribuidas en 2 Zonas de Disponibilidad (us-east-1a / us-east-1b) para alta disponibilidad y cumplimiento estricto de privacidad.

VPC País (Ej: VPC-Argentina 10.0.0.0/16)

Punto de entrada exclusivo. Contiene el Application Load Balancer (ALB) expuesto y los NAT Gateways redundantes.

2. Capa Privada NAT / Endpoints

Bases de Datos e In-Memory Cache. Sin rutas hacia NAT Gateway ni Internet Gateway bajo ninguna circunstancia.

AZ-b: 10.0.13.0/24 (Isolated DB)

🔀 Estrategia de Salida a Internet y VPC Endpoints (Privatelink)

Optimizando seguridad y costos operacionales mediante tráfico interno en la red de AWS.

🛡️ NAT Gateways (Multi-AZ)

Ubicados en las subredes públicas de cada AZ. Permiten a las tareas ECS Fargate realizar llamadas salientes hacia APIs de terceros (ej. pasarelas de pago o sistemas de aseguradoras) sin quedar expuestas a conexiones entrantes.

⚡ VPC Interface & Gateway Endpoints

Para evitar que el tráfico a servicios gestionados pase por internet o NAT Gateway (ahorrando costos de datos), se configuran Endpoints privados para:

  • S3 (Gateway Endpoint)
  • ECR (Interface Endpoint para pull de imágenes Docker)
  • Secrets Manager & CloudWatch Logs

🌍 Enrutamiento Multi-País Bajo un Único Dominio

Estrategia para ofrecer localización por país (moneda, precios, features) utilizando Amazon Route 53 y CloudFront.

1. Geo-Location Routing

Route 53 detecta la IP del paciente/médico y resuelve a la CDN/ALB de su país de origen automáticos.

2. Ruteo por Path de URL

CloudFront o el ALB derivan el tráfico según la ruta: /ar/api/..., /cl/api/...

3. Aislamiento Backend

Cada petición termina en la VPC aislada del país correspondiente, garantizando soberanía de datos.

📘 Criterios de Diseño, Racional de Redes y Decisiones de Arquitectura (ADRs)

Fundamentos técnicos, de costos y seguridad que justifican la topología de VPCs aisladas, capas de subredes e interconexión de red para VitalMed.

🏥 Requerimientos Operativos y Aislamiento Sanitario

Para garantizar el cumplimiento de las normativas de datos de salud en Latinoamérica, se diseñó un esquema de red donde las bases de datos y datos sensibles nunca tocan la red pública. Cada entorno nacional opera sobre un espacio de direccionamiento IP segregado, previniendo el tráfico lateral no autorizado entre países y acotando el riesgo frente a eventuales ciberataques.

ADR-NET-001 Aprobado

Topología de 3 Capas (Pública, Privada, Aislada)

Criterio evaluado: Protección en profundidad para datos de historias clínicas electrónicas (HCE).

Decisión: Separar subredes en Públicas (ALB/NAT), Privadas (Compute/ECS) y Aisladas (Bases de Datos Aurora/Cache) sin tabla de ruteo hacia internet para la capa aislada.

✓ Beneficio: Imposibilidad matemática de acceso directo desde internet a la base de datos, cumpliendo normativas HIPAA/GDPR localizadas.

ADR-NET-002 Aprobado

VPC Endpoints (Privatelink) vs. Tráfico por NAT Gateway

Criterio evaluado: Reducción de costos por procesamiento de datos en NAT Gateway y mejora de la seguridad del tráfico interno.

Decisión: Implementar Gateway Endpoints (S3) e Interface Endpoints (ECR, Secrets Manager, Logs) dentro de la VPC privada.

✓ Beneficio: Las llamadas a los servicios gestionados de AWS no consumen ancho de banda de salida a internet y se mantienen dentro del backbone seguro de AWS.

ADR-NET-003 Aprobado

Tráfico Multimedia Fuera de la VPC (Amazon Chime SDK)

Criterio evaluado: Prevención de saturación de NAT Gateways y costos elevados en llamadas de videoconferencia WebRTC.

Decisión: Enrutar las videoconsultas en vivo directamente cliente-servidor mediante el SDK de Amazon Chime sin pasar por los contenedores ni la VPC.

✓ Beneficio: Menor latencia en videollamadas y disminución drástica del costo por transferencia de datos en los cómputos de la VPC.

ADR-NET-004 Aprobado

Ausencia de Peering Directo Entre VPCs de Trabajo (No Mesh)

Criterio evaluado: Prevención de movimientos laterales no autorizados y aislamiento estricto por cuenta-país.

Decisión: Desestimar enlaces VPC Peering o Transit Gateway de interconexión directa entre las VPCs de Argentina, Chile, Colombia y México.

✓ Beneficio: Garantiza la soberanía de los datos de cada nación sin riesgo de exposición cruzada ante un incidente de red en algún país.

ADR-NET-005 Supuesto explícito

Despliegue Mono-Región (us-east-1) con Redes Separadas

Criterio evaluado: AWS no cuenta con región propia en Argentina, Chile ni Colombia; México posee región reciente. Desplegar redes multi-región aumentaría drásticamente los costos de transferencia de datos inter-region y la complejidad operativa para el equipo técnico.

Decisión (supuesto): Todas las VPCs se provisionan dentro de la región us-east-1, utilizando espacios CIDR diferenciados e independientes por cuenta de país, asegurando el aislamiento lógico y operativo.

✓ Beneficio: Simplicidad de mantenimiento y optimización de presupuesto. ⚠️ Trade-off: Un evento de interrupción total en la región us-east-1 impactará globalmente a todas las VPCs.

🔄 Flujo de Inspección y Tránsito de Red (Ingreso a Almacenamiento)

Paso 1: Resolución y CDN

Route 53 geolocaliza la petición y la envía a la capa Edge de CloudFront con inspección WAF.

Paso 2: Entrada Pública

El Application Load Balancer (ALB) de la Subred Pública recibe el tráfico filtrado en la AZ correspondiente.

Paso 3: Cómputo Privado

El ALB reenvía la solicitud hacia los contenedores ECS Fargate ejecutándose en la Subred Privada.

Paso 4: Consulta Aislada

ECS realiza la consulta a la base de datos Aurora PostgreSQL en la Subred Aislada (sin salida a internet).
